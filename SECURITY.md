# Security Policy

## Supported versions

This project is under active development. Security fixes are applied to the latest code on the `main` branch.

| Version | Supported |
| --- | --- |
| `main` | ✅ |
| Older commits / local copies | ❌ |

## Reporting a vulnerability

Please do **not** disclose security vulnerabilities, exploit details, credentials, learner data, or other sensitive information in a public issue.

Prefer GitHub's private vulnerability reporting / Security Advisory flow for this repository when available.

If private reporting is not available, open a public issue that contains only a short request for a private contact channel. Do not include the vulnerability details in that issue.

When reporting privately, include where possible:

- a clear description of the issue;
- affected files, commands, or versions;
- steps to reproduce;
- expected and actual behaviour;
- potential impact;
- any suggested mitigation.

## Sensitive educational data

This repository is designed to keep learner-identifiable information and local teaching inputs out of version control. If you discover student names, contact details, private assessment data, credentials, tokens, official-source PDFs, or other material that should not be public, report it privately as a security/privacy issue.

## Response expectations

Reports will be acknowledged and assessed as soon as practical. Confirmed issues will be fixed on `main`, with disclosure coordinated after a remediation is available when appropriate.
