# Accessibility and format statement

## Primary presentation format

Use `slides.html` for classroom presentation and keyboard-based access. It is a self-contained Reveal.js deck with document language and viewport metadata, keyboard navigation, visible focus, reduced-motion support, descriptive text alternatives, long descriptions, and slide-specific speaker notes. Automated axe checks run during rendering. A human visual review is still required after any content or theme change.

## PDF limitation

`slides.pdf` is a print-reference copy generated by DeckTape. It preserves the visual pages but is currently untagged, so it must not be represented as an accessible PDF or used as the only learner-facing format. Provide `slides.html` alongside it. The publication validator blocks publication-ready status until the slide PDF is tagged and its reading order has been manually verified.

## Teacher and learner documents

The HTML versions of the teacher notes, delivery guide, worksheet, practical, homework, and answers are the primary structured formats. Their PDFs are convenience print copies. Before distributing adapted copies, retain headings, table headers, reading order, text alternatives, and sufficient contrast.

## Classroom adjustments

- Describe diagrams and relationship models aloud using the supplied long descriptions.
- Do not rely on colour, icons, animation, connectivity, or device interaction alone to communicate meaning.
- Allow learners to use the HTML deck at their preferred zoom level.
- Provide the teacher delivery guide separately; speaker notes are not visible to learners in the projected view.
- Offer printed or offline equivalents for network, mobile, or cloud scenarios.
- Use only the fictional datasets supplied with the package.
