# Teacher notes: Input–process–output models

## Curriculum boundary

Use the abstract input–process–output model, time value of information, and computer appropriateness. Do not teach computer hardware categories here; those belong to 1.4.

## Core explanation

An input–process–output model describes what enters a transformation, what rules or actions transform it, and what result is produced. It abstracts away implementation details so a proposed information task can be discussed and tested. A strong model names the required data, transformation, intended information output, user, and purpose.

Information often has its highest value when it can still influence a decision. Value may decline when an output arrives late, even if it remains accurate. Computers are suitable for high-volume repetition, rapid calculation, storage, retrieval, and consistent rule application. Human judgement remains important when requirements are ambiguous, ethical trade-offs matter, or exceptions cannot be reduced to safe rules.

## Four-period guidance

1. Model a fictional canteen’s daily total. Compare vague labels (“numbers → calculate → answer”) with specific inputs, formula, output, user, and purpose.
2. Give incomplete models. Learners identify missing units, rules, exception handling, or output context.
3. Order scenarios by how quickly information loses value: emergency warning, seat availability, annual inventory trend, historical archive.
4. Use `practical.md`; require an appropriateness recommendation, not automatic computerisation.

## Misconceptions

- Process is a transformation, not merely “use a computer.”
- Output is not automatically information unless it has meaning for a purpose.
- Accurate information can lose value when late.
- A computer is not always the most appropriate solution.

## Accessibility and privacy

Allow models as labelled boxes, tables, or structured text. Use fictional operational data only.
